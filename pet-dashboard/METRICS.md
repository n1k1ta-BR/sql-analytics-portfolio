# Метрики и фильтры

| Задача | SQL-файл | Что показывает дашборд |
|---|---|---|
| 1 | `01_ltv_segments.sql` | Число пользователей, средний и суммарный LTV по числу оплаченных заказов |
| 2 | `02_top_products.sql` | До трёх товаров в каждой паре «месяц × категория», с ранжированием по выручке |
| 3 | `03_viewed_not_purchased.sql` | Уникальные пары «пользователь × категория»: был просмотр, нет оплаченной покупки |
| 4 | `04_promo_codes.sql` | Промокоды с 20+ оплаченными заказами, выручка и средний чек |
| 5 | `05_repeat_rate.sql` | Доля повторных покупателей по городам и общая доля |
| 6 | `06_activation_rate.sql` | Активация по каналу: хотя бы один оплаченный заказ в дни 0–6 |
| 7 | `07_anomalous_orders.sql` | Заказы строго дороже тройного среднего предыдущих оплаченных заказов |

`00_sales.sql` и `00_monthly.sql` добавляют общий обзор продаж.

## Основные правила

- Выручка позиции: `quantity * price`; учитывается только `status = 'paid'`.
- Количество заказов считается на уровне заказа. Средний чек — средняя сумма заказа, а не позиции.
- LTV — оплаченная выручка пользователя за доступную историю. Пользователи без покупок имеют LTV = 0.
- Покупатель имеет минимум один оплаченный заказ; повторный покупатель — минимум два. Общая доля равна числу повторных покупателей / числу покупателей, а не среднему арифметическому долей городов.
- В задаче 5 на графике показаны все города. По умолчанию таблица содержит только города выше общей доли, как требует исходная задача.
- В задаче 2 равенство выручки разрешается через `product_id ASC`.
- В задаче 3 наличие покупки проверяется за весь период, независимо от порядка просмотра и покупки. Пользователь может присутствовать в нескольких категориях; сумма по категориям не равна числу уникальных пользователей.
- В задаче 7 порядок заказов: `order_date, order_id`. Рамка окна — от первого до предыдущего заказа; текущий заказ исключён. Первый заказ не попадает в результат. Вычисления выполняются без раннего округления.
- Показатели денег используют REAL, как в исходном учебном задании; подпись — «у.е.», поскольку валюта не задана.
- В UI доли показаны в процентах, в CSV — числами от 0 до 1. Форматирование таблиц не меняет вычисления.

## Область действия фильтров

| Фильтр | Область |
|---|---|
| Канал привлечения слева | Все показатели выбранного раздела, по пользователям этого канала |
| Период заказов | Только раздел «Продажи»; обе даты включительно, исходные даты имеют формат YYYY-MM-DD |
| Месяц и категория в топе | График и таблица топ-3; не меняют KPI или промокоды |
| Категория просмотров | Только таблица пар «пользователь × категория» |
| Только города выше общей доли | Только таблица повторных покупок |

При выборе части месяца топ и месячная выручка относятся только к выбранным дням. Исторические метрики в двух других разделах не зависят от периода продаж.

Синтетические события исходного генератора могут предшествовать регистрации. Дашборд сохраняет правила исходной задачи о просмотрах и не превращает их в событийную воронку. Эти данные предназначены для демонстрации SQL, а не для бизнес-рекомендаций.
