# Интернет-магазин: продажи и покупатели

Дашборд Apache Superset для проекта
[SQL E-commerce Analytics](../README.md).

Показывает продажи интернет-магазина, поведение покупателей
и показатели товаров на синтетических данных.


## Основные показатели

В расчётах продаж учитываются только заказы со статусом `paid`.

| Показатель | Расчёт |
|---|---|
| Выручка | Сумма `quantity × price` по позициям оплаченных заказов |
| Оплаченные заказы | Количество уникальных оплаченных заказов |
| Покупатели | Количество пользователей хотя бы с одним оплаченным заказом |
| Средний чек | Выручка / количество оплаченных заказов |

Обозначения на карточках: `k` — тысячи, `M` — миллионы.
Денежные показатели на дашборде подписаны в рублях.

## Визуализации

- Динамика выручки по месяцам.
- Распределение пользователей по числу оплаченных заказов.
- Топ-3 товара по выручке внутри категории за месяц.
- Распределение активированных пользователей по каналам привлечения.
- Доля повторных покупателей по городам.
- Показатели промокодов: заказы, выручка и средний чек.

### Активация

Пользователь считается активированным, если совершил оплаченный
заказ в интервале:

`[дата регистрации; дата регистрации + 7 дней)`

Круговая диаграмма показывает долю каждого канала среди всех
активированных пользователей. Это не процент активации внутри канала.

### Повторные покупки

Повторный покупатель — пользователь с двумя и более оплаченными
заказами.

Доля повторных покупателей города:

`повторные покупатели города / все покупатели города`

Пользователи без оплаченных заказов в знаменатель не входят.

### Топ товаров

Рейтинг рассчитывается отдельно для каждого месяца и категории.
Для просмотра одного рейтинга необходимо выбрать один месяц
и одну категорию.

### Промокоды

Учитываются промокоды минимум с 20 оплаченными заказами.
Средний чек рассчитывается на уровне заказа.

Показатели описывают заказы с промокодами и сами по себе
не доказывают влияние промокодов на продажи.

## Фильтры

| Фильтр | Область действия |
|---|---|
| Город | Карточки продаж, динамика выручки, активированные пользователи по каналам и повторные покупки по городам |
| Период продаж | Четыре карточки продаж и динамика выручки по дате заказа |

Область действия задаётся в настройках `Scoping`.
Показатели, рассчитанные за весь период, не меняются при выборе
периода продаж.

## Источники данных

Исходный проект использует SQLite и Python для генерации данных.
Для дашборда данные загружены в PostgreSQL.

| Таблица PostgreSQL | Содержимое |
|---|---|
| `USERS` | Пользователи, регистрация, город и канал привлечения |
| `ORDERS` | Заказы, даты, статусы и промокоды |
| `ORDER_ITEMS` | Позиции заказов, количество и цена |
| `PRODUCTS` | Товары, категории и бренды |
| `EVENTS` | События пользователей |

Названия таблиц в SQL-запросах заключены в двойные кавычки,
поскольку используются заглавные буквы.

## Восстановление дашборда

1. Подготовить PostgreSQL и Apache Superset.
2. Получить исходные данные проекта. Генератор находится
   в [`scripts/generate_data.py`](../scripts/generate_data.py).
3. Загрузить пять исходных таблиц в PostgreSQL с названиями,
   указанными выше.
4. Проверить типы дат:
   - `USERS.signup_date`;
   - `ORDERS.order_date`;
   - `EVENTS.event_time`.
5. В Superset открыть раздел `Dashboards` и импортировать
   [`dashboard_export.zip`](dashboard_export.zip).
6. Указать параметры подключения к своей базе PostgreSQL.
7. Проверить датасеты, обновить графики и проверить область
   действия фильтров.

ZIP содержит конфигурацию дашборда, графиков и датасетов.
Исходные строки таблиц в экспорт не входят.

## Ограничения

Данные синтетические и предназначены для демонстрации
SQL-аналитики и визуализации. Динамика показателей не является
оценкой реального бизнеса.

в работающий экземпляр Apache Superset.
