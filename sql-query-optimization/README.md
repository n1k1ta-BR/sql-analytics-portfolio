# SQL Query Optimization

Учебный pet-проект по оптимизации SQL-запросов в SQLite: индексы, предварительная агрегация и изменение структуры запросов с проверкой результата через `EXPLAIN QUERY PLAN`.

**Стек:** SQLite, SQL, Python, pandas, NumPy.

## Задачи

1. Замена функции `substr` в фильтре по месяцу на диапазон дат.
2. Составной покрывающий индекс `(status, order_date, user_id)`.
3. Агрегация позиций заказа до соединения с другими таблицами.
4. Индекс для коррелированного подзапроса `NOT EXISTS`.
5. Получение последних событий пользователя без временной сортировки.
6. Замена `JOIN + DISTINCT` на `EXISTS` с сохранением набора пользователей.
7. Выбор трёх индексов под заданную нагрузку и описание их компромиссов.

## Структура

- `sql/01`–`sql/06` — исходные и оптимизированные запросы, необходимые индексы.
- `sql/07` — три индекса и запросы для проверки индексного бюджета.
- `scripts/` — генерация базы и сравнение решений.
- `notebooks/optimization.ipynb` — исходный учебный ноутбук с решениями, без сохранённых выводов.
- `docs/` — условия задач и объяснения решений.
- `results/` — планы до и после, отчёт проверки и сведения об окружении.

## Запуск

Требуется Python 3.11+. Из корня проекта:

```bash
python -m venv .venv
```

Активация на macOS / Linux: `source .venv/bin/activate`.
На Windows PowerShell: `.venv\Scripts\Activate.ps1`.

```bash
python -m pip install -r requirements.txt
python scripts/generate_data.py
python scripts/compare.py
```


Для работы в Colab загрузите `notebooks/optimization.ipynb` и выполните ячейки сверху вниз.

## Результаты

Все 7 решений получили **100/100** в исходной учебной автопроверке. Подробности: [results/comparison.txt](results/comparison.txt), сводка: [results/summary.csv](results/summary.csv).

Время выполнения приведено для иллюстрации и зависит от окружения. Для задачи 4 исходный `NOT EXISTS` без индекса не запускается на полной базе; для задачи 6 эквивалентность проверяется на уменьшенном наборе. Это режимы исходной автопроверки. Снижение времени не является обязательным результатом каждой переписи запроса.

В задаче 1 `BETWEEN` корректен для дат в формате `YYYY-MM-DD`, используемом в данных. В задаче 5 порядок событий с одинаковой датой не определён; для стабильного порядка потребовался бы дополнительный ключ сортировки.
